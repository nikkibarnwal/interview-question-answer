React Fiber को एकदम आसान शब्दों में समझने के लिए एक रीयल-लाइफ कहानी (Restaurant Example) से शुरू करते हैं। इसके बाद आपका माइंडसेट ऐसा हो जाएगा कि आप इसे कभी नहीं भूलेंगे।

## ☕ एक आसान कहानी: "पुराना हलवाई vs नया स्मार्ट शेफ"
मान लीजिए एक बहुत बड़ी शादी है, जहाँ 500 मेहमान आए हैं।


* React 15 (Old Engine - Stack Reconciler): यह एक पुराने ज़माने के ज़िद्दी हलवाई जैसा था. इसके पास एक बार में एक ही काम करने की क्षमता थी। अगर इसने 50 पाउंड (kg) बूंदी के लड्डू बनाना शुरू कर दिया, तो यह बीच में नहीं रुकता था। चाहे मुख्य मेहमान (Chief Guest) आकर चिल्लाए कि "अरे, मुझे तुरंत पानी चाहिए!", हलवाई बोलता—"पहले लड्डू पूरे बनेंगे, फिर पानी मिलेगा।" नतीजा? मुख्य मेहमान गुस्सा हो जाता (यानी आपका वेब पेज हैंग या फ्रीज हो जाता)। [1] 
* React 16+ (New Engine - React Fiber): यह एक मॉडर्न और स्मार्ट शेफ है. यह काम को छोटे-छोटे हिस्सों (Units of work) में बांट देता है. यह लड्डू बना रहा है, लेकिन जैसे ही मुख्य मेहमान (High-priority task जैसे कि User Click या Animation) आता है, यह लड्डू बनाना वहीं पर रोक (Pause) देता है. पहले मेहमान को पानी देता है (UI स्मूथ रखता है), और फिर वापस आकर लड्डू बनाना वहीं से शुरू (Resume) कर देता है. [2, 3] 
  

------------------------------
## 🧠 तो React Fiber असल में क्या है?
React Fiber, React कोर का एक रीराइट (complete rewrite) आर्किटेक्चर है, जिसे React 16 में इंट्रोड्यूस किया गया था. यह React का नया Reconciliation Engine (बदलावों को पहचानने और लागू करने वाला दिमाग) है. 
इसका सबसे बड़ा मकसद है: वेब ऐप्स की परफॉर्मेंस और रिस्पॉन्सिवनेस को नेक्स्ट लेवल पर ले जाना, खासकर तब जब भारी एनिमेशन या बहुत सारे यूज़र इनपुट एक साथ आ रहे हों. 
------------------------------
## ⚡ Fiber काम कैसे करता है? (The Superpowers)
इसके पास 4 जादुई ताकतें (Core Features) हैं:

   1. काम को टुकड़ों में तोड़ना (Time Slicing): यह पूरे UI रेंडरिंग के काम को छोटे-छोटे 'Fibers' (units of work) में बांट देता है. 
   2. काम को रोकना और शुरू करना (Pause, Resume & Restart): अगर ब्राउज़र के पास कोई ज़रूरी काम आ जाए, तो React Fiber अपने रेंडरिंग टास्क को बीच में ही रोककर ब्राउज़र को रास्ता दे देता है, और बाद में वहीं से काम शुरू करता है.
   3. प्राथमिकता तय करना (Prioritization): यह तय करता है कि कौन सा काम पहले होना चाहिए.
   * High Priority: यूज़र का बटन क्लिक करना, इनपुट बॉक्स में टाइप करना, या एनिमेशन (यह तुरंत दिखना चाहिए).
      * Low Priority: बैकग्राउंड में डेटा लोड होना या नीचे का कोई फुटर रेंडर होना. 
   4. पुरानी मेहनत का इस्तेमाल (Reuse completed work): अगर कोई काम पहले ही हो चुका है और उसमें कोई बदलाव नहीं हुआ, तो यह उसे दोबारा नहीं करता. 

------------------------------
## ⚙️ यह पर्दे के पीछे कैसे चलता है? (Two Phases)
React Fiber पूरे काम को दो हिस्सों में पूरा करता है: 

| 1. रेंडर फेज (Render Phase) 🛑 | 2. कमिट फेज (Commit Phase) 🚀 |
|---|---|
| यह पूरी तरह से Asynchronous होता है। | यह पूरी तरह से Synchronous होता है। |
| इसमें React सिर्फ हिसाब-किताब लगाता है कि UI में क्या बदलना है (Virtual DOM में बदलाव ढूंढ़ना)। | इसमें React सीधे जाकर Real DOM को अपडेट कर देता है। |
| इस फेज को बीच में रोका (Interrupt) जा सकता है अगर कोई ज़रूरी काम आ जाए। | इसे बीच में नहीं रोका जा सकता, यह एक बार में ही पूरा होता है ताकि UI टूटा हुआ न दिखे। |

## 📝 React Fiber: Ultimate Revision Notes## 1. Quick Introduction (What is it?)

* React Fiber React 16 में आया हुआ एक बिल्कुल नया Core Architecture / Engine है।
* यह React का नया Reconciliation Engine है, जो यह तय करता है कि UI में कौन से बदलाव कब और कैसे अपडेट होंगे।
* Main Goal: टूटे हुए या अटके हुए UI (laggy UX) को खत्म करना और वेब ऐप्स को सुपर-फास्ट और रिस्पॉन्सिव बनाना।

------------------------------
## 2. The Core Superpowers (Core Features)
React Fiber के पास 4 सबसे बड़ी ताकतें हैं:

* Time Slicing (टुकड़ों में काम): यह बड़े रेंडरिंग टास्क को छोटे-छोटे Units of Work (Fibers) में तोड़ देता है।
* Pause, Resume & Restart: यह चलते हुए रेंडरिंग काम को बीच में Pause कर सकता है, ब्राउज़र को दूसरा ज़रूरी काम करने का मौका दे सकता है, और फिर वापस आकर काम को वहीं से Resume कर सकता है।
* Prioritization (VIP Treatment): यह टास्क की इम्पोर्टेंस (Priority) तय करता है।   
   * High Priority: User clicks, Typing, Animations (इन्हें तुरंत रेंडर करता है)।   
   * Low Priority: Fetching data, Footer rendering (इन्हें बाद के लिए रोक सकता है)।   
* Double Buffering (गेमिंग जैसी टेक्निक): React बैकग्राउंड में हमेशा 2 Trees मेंटेन करता है:   
   1. Current Tree: जो अभी स्क्रीन पर दिख रहा है।
   2. Work-in-Progress (WIP) Tree: जो बैकग्राउंड में अपडेट हो रहा है।
   * Benefit: जब WIP Tree तैयार हो जाता है, तो React तुरंत पॉइंटर स्विच कर देता है। इससे यूज़र को कभी भी आधा-अधूरा (broken) UI नहीं दिखता।

------------------------------
## 3. The Data Structure: Singly Linked List 🕸️
पुराना React (Stack Reconciler) Stack डेटा स्ट्रक्चर पर चलता था, जिसे बीच में रोका नहीं जा सकता था।
React Fiber एक Singly Linked List पर चलता है। यहाँ हर कंपोनेंट एक Fiber Node (JavaScript Object) है, जिसके पास 3 जादुई पॉइंटर्स होते हैं:   

* child: सिर्फ और सिर्फ अपने पहले बच्चे (First Child) की तरफ इशारा करता है।   
* sibling: अपने ठीक बगल वाले भाई/बहन (Next Brother/Sister) की तरफ इशारा करता है।    
* return: वापस अपने पैरेंट (Parent) की तरफ इशारा करता है, ताकि काम पूरा होने पर वहाँ लौटा जा सके।

## 4. The Phases of Fiber (Execution Flow) ⚙️
React Fiber पूरे काम को दो अलग-अलग फेज में पूरा करता है:

| Phase 1: Render Phase 🛑 | Phase 2: Commit Phase 🚀 |
|---|---|
| यह पूरी तरह से Asynchronous होता है। | यह पूरी तरह से Synchronous होता है। |
| इसमें React सिर्फ हिसाब-किताब लगाता है (Computes changes in Virtual DOM)। | इसमें React सीधे Real DOM में बदलावों को अप्लाई कर देता है। |
| इसे बीच में रोका (Interrupt) जा सकता है अगर कोई High-Priority काम आ जाए। | इसे बीच में नहीं रोका जा सकता। यह एक बार में ही पूरा होता है। |
