Good attempt 👍 **Final output is correct:**

```text
A G E C F D B
```

But there is **one important correction** in your reasoning around `D` and `F`. This is exactly the kind of detail L2 interviewers may probe.

### Let's trace the queues

Synchronous:

```text
A
G
```

Initial queues:

```text
nextTick:
[E]

Promise microtask:
[C]
```

So far correct. ✅

---

### First: `nextTick E`

`E` executes:

```js
process.nextTick(() => {
  console.log("E");

  Promise.resolve().then(() => {
    console.log("F");
  });
});
```

Output:

```text
E
```

While `E` is executing, it schedules:

```text
Promise → F
```

So the Promise queue now becomes:

```text
[C, F]
```

---

### Then Promise microtasks

`C` executes:

```text
C
```

During `C`:

```js
process.nextTick(() => {
  console.log("D");
});
```

So `D` is added to the **nextTick queue**.

But here's the subtle part:

At this point we're **already draining the Promise microtask queue**.

So `F` is already waiting in that same Promise queue:

```text
Promise queue:
[F]
```

Therefore:

```text
C
F
```

execute before the newly scheduled `D`.

After the current microtask processing, Node processes the newly scheduled nextTick:

```text
D
```

So:

```text
E → C → F → D
```

Your final order is right. ✅

But your statement:

> "once current phase will end then nextTick will pick"

I'd replace with:

> **"Because D was scheduled from inside a Promise microtask, the current microtask processing continues; F was already queued and executes before D. After the microtask checkpoint, Node processes the nextTick queue."**

That's a much safer L2 explanation.

---

### Finally `B`

`setImmediate`:

```js
setImmediate(() => {
  console.log("B");
});
```

runs in the **check phase**, after the current synchronous execution and microtask processing.

So final:

```text
A
G
E
C
F
D
B
```
