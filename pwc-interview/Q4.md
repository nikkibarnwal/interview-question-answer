### 🔥 PwC Interview Question #4
[SSE](https://github.com/nikkibarnwal/interview-question-answer/blob/main/pwc-interview/Q3-LCP-INP-SSE.md)

> **"Suppose your React application receives an LLM response token-by-token through SSE. If the server sends hundreds of updates per second, React could potentially re-render hundreds of times. How would you design the UI to handle this efficiently?"**

### 🎤 Strong Interview Answer

> If the server sends hundreds of updates per second, I wouldn't update React state for every individual token because that could cause excessive re-renders and make the UI sluggish.
>
> Instead, I would buffer the incoming tokens and update the React state in batches at a controlled frequency.
>
> For example, I could accumulate incoming tokens in a `useRef`, and periodically flush the accumulated content into React state using a timer or `requestAnimationFrame`.
>
> The basic flow would be:
>
> ```text
> SSE Stream
>     ↓
> Incoming tokens
>     ↓
> Buffer in useRef
>     ↓
> Batch updates
>     ↓
> React state
>     ↓
> UI render
> ```
>
> `useRef` is useful for the buffer because changing a ref doesn't itself trigger a React render.
>
> I would also make sure that only the component responsible for displaying the streaming response is updated rather than causing the entire chat application to re-render.
>
> For expensive child components, I could use `React.memo`, and if the conversation contains a large number of messages, I could use virtualization so that only visible messages are rendered.
>
> I would also profile the application using React DevTools Profiler and browser performance tools to determine the actual rendering bottleneck before applying optimizations.
>
> So the main idea is **don't render for every token; buffer the stream, batch updates, isolate the state, and render only what is necessary.**

### ⭐ Remember this diagram

```text
             LLM
              ↓
          SSE Stream
              ↓
        Token-by-token
              ↓
          useRef Buffer
              ↓
       Batch / Throttle
              ↓
          setState()
              ↓
        Small React tree
              ↓
             UI
```

### One important correction

Don't say:

> "I'll use `useCallback` to prevent all these renders."

`useCallback` **doesn't prevent a component from rendering by itself**. It mainly helps maintain function identity when passing callbacks to memoized children or when dependencies matter.

For this problem, the strongest concepts are:

**buffering + batching + state isolation + virtualization + profiling.**
